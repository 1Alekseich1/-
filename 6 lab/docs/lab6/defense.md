# Подготовка к защите ЛР №6

1. **Для чего Router?** Меняет экран по адресу без полной перезагрузки приложения. `NavLink` подчёркивает текущую ссылку, `Outlet` размещает вложенную страницу.
2. **Как работают фильтры в URL?** `useSearchParams` читает `q`, `genre`, `sort`, `page`. Ссылку можно скопировать и открыть в новой вкладке.
3. **Зачем useDebounce?** Не отправляем запрос на каждую букву: задержка 350 мс.
4. **Зачем AbortController?** Прерывает старый запрос при смене фильтра и размонтировании.
5. **Зачем Context?** Для глобальных темы и пользователя. Каталог не помещаем в Context.
6. **Зачем Zod?** Одна схема валидации для всех полей и сравнения количества свободных и общих экземпляров. Тип выводится через `z.infer`.
7. **Чем 409 отличается от 422?** 409 — конфликт (повтор ISBN), 422 — не прошли проверки полей. Они связываются с `setError` и `aria-describedby`.
8. **Где сервер?** В ЛР №6 backend ещё нет: Open Library используется для поиска и просмотра, а добавление/редактирование симулирует API и сохраняется локально. Реальный FastAPI добавляется в следующих работах.

## Показ ошибок

- Неправильный ISBN → ошибка Zod.
- Свободных больше, чем всего → межполевая ошибка.
- Создать запись дважды с одинаковым ISBN → 409.
- Ввести точное название `ошибка 422` → имитация серверной ошибки поля.
- Ввести точное название `ошибка 500` → общая ошибка формы.
- Открыть `/wishlist` без входа → перенаправление `/login`.
- Включить вкладку Network → быстро менять запрос и показать отмену запроса.
