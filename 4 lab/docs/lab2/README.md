# ЛР №2 — проверка интерфейса

CSS создан по принципу **mobile-first**. Файлы: `styles/tokens.css`, `base.css`, `layout.css`, `components.css`.

## Проверить и снять скриншоты

1. Откройте `index.html` через Live Server. Откройте DevTools (F12) → Toggle device toolbar.
2. Проверьте **375, 768, 1440 px**. На 375 одна колонка; 768 — две; 1440 — 3 колонки в каталоге и боковая панель фильтров.
3. Для каждой ширины: DevTools → Rendering → Emulate CSS media feature `prefers-color-scheme`: `light`, затем `dark`. Сохраните настоящие скриншоты в `docs/lab2/screenshots/` с именами `375-light.png`, `375-dark.png`, `768-light.png`, `768-dark.png`, `1440-light.png`, `1440-dark.png`.
4. Проверьте 320 px и отсутствие горизонтального скролла на всех трёх страницах.
5. Нажимайте Tab — фокус должен быть виден. Эмулируйте `prefers-reduced-motion: reduce`.
6. DevTools → Lighthouse → Performance и Accessibility. Сохраните реальные результаты; измерения в проект не подставлены.

Всего **3 media queries**: тёмная тема, снижение анимации и десктопная раскладка. Сетка в каталоге адаптируется сама без breakpoints.

## Почему это работает

* `:root` хранит общие токены, поэтому смена темы изменяет только переменные, а не стили карточек.
* `auto-fit` и `minmax()` размещают максимально возможное число книг в строке.
* У `.book-card` `display:flex`, у `.book-card__action` `margin-top:auto`: кнопка располагается снизу (это не межсиблинговый отступ).
* `.page` задаёт flex-колонку по высоте окна, `margin-top:auto` у футера держит его снизу.
